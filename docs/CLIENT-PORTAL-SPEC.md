# مواصفات واجهة العميل في أليف

## الهدف
منح مالك الحيوان مساحة شخصية واضحة تعرض كل ما تسمح العيادة بنشره عن حيواناته، مع حماية كاملة تمنع رؤية بيانات أي عميل آخر.

## خريطة الصفحات

### 1. الدخول والأمان
- دخول بالموبايل أو البريد وكلمة المرور.
- OTP للتحقق والاستعادة، وإظهار الأجهزة والجلسات النشطة.
- موافقة الشروط والخصوصية وتفضيلات الرسائل.

### 2. الرئيسية
- تحية باسم العميل وصورة الحيوان النشط.
- بطاقة الموعد القادم وإجراء تأكيد/إعادة جدولة.
- تنبيه تطعيم أو متابعة أو نتيجة جديدة.
- الرصيد الحالي وآخر فاتورة.
- Quick actions: احجز موعدًا، تواصل، افتح ملف الحيوان.

### 3. حيواناتي
- بطاقات لكل حيوان: صورة، الاسم، النوع، العمر، السلالة، آخر وزن، microchip.
- Status chips للتطعيم والمتابعة والحساسية.
- تبديل الحيوان يحفظ الاختيار في الجلسة.

### 4. ملف الحيوان
- Overview: البيانات الأساسية والحساسية والأمراض المزمنة والطعام.
- Timeline: زيارات وتطعيمات ونتائج وعمليات ومواعيد.
- Visits: الملخص المنشور، التشخيص، الخطة، تعليمات الخروج، المتابعة.
- Prescriptions: الدواء والجرعة والتكرار والمدة والتحذيرات.
- Vaccinations: السابق والقادم وشهادة PDF.
- Labs & Imaging: النتائج المعتمدة والمرفقات المسموح بها.
- Weight: رسم زمني وتاريخ القياسات.
- Documents: شهادات وموافقات وإيصالات.

### 5. المواعيد
- اختيار الحيوان والخدمة والفرع والطبيب أو أول متاح.
- Slots حقيقية مع منع التعارض.
- إلغاء/إعادة جدولة حسب cutoff policy.
- حالة الطلب: مطلوب، مؤكد، وصل، مكتمل، ملغي، لم يحضر.

### 6. الفواتير
- قائمة الفواتير وحالتها والإجمالي والمدفوع والمتبقي.
- تفاصيل البنود والخصم والضريبة والمدفوعات.
- تنزيل فاتورة/إيصال PDF، والدفع الإلكتروني لاحقًا.

### 7. الرسائل والإشعارات
- Inbox للرسائل المهمة ونتائج النشر وتذكيرات التطعيم.
- تفضيل WhatsApp/SMS/Email وتعطيل الرسائل التسويقية منفصلًا.

### 8. الحساب والخصوصية
- تعديل الهاتف والبريد والعنوان عبر تحقق.
- إدارة كلمة المرور والجلسات والأجهزة.
- طلب نسخة من البيانات أو تصحيحها وفق سياسة العيادة.

## الحالات التي يجب تصميمها
- عميل بلا حيوانات، بلا مواعيد، بلا فواتير، أو بلا نتائج.
- ملف طبي غير منشور، نتيجة قيد المراجعة، دفعة فاشلة.
- جلسة منتهية، اتصال بطيء، خادم غير متاح.
- حيوان متوفى: واجهة محترمة دون تذكيرات غير مناسبة.
- أكثر من عشرة حيوانات: بحث وتصفية بدلاً من شريط بطاقات طويل.

## API المقترح
- `GET /api/client/me`
- `PATCH /api/client/me`
- `GET /api/client/pets`
- `GET /api/client/pets/:petId`
- `GET /api/client/pets/:petId/timeline`
- `GET /api/client/appointments`
- `POST /api/client/appointment-requests`
- `PATCH /api/client/appointment-requests/:id`
- `GET /api/client/invoices`
- `GET /api/client/invoices/:id/pdf`
- `GET /api/client/notifications`
- `PATCH /api/client/preferences`

لا يقبل أي endpoint قيمة `ownerId` من العميل. يتم استخراجها دائمًا من الجلسة.

## سياسة نشر المعلومات الطبية
- الحقول الداخلية وملاحظات الفريق لا ترسل للبوابة.
- الزيارة لا تظهر إلا بعد اعتمادها وتحديد `publishedToClientAt`.
- النتائج لا تظهر إلا بعد اعتماد الطبيب أو مسؤول المعمل.
- تعديل محتوى منشور ينشئ نسخة وتدقيقًا، ولا يستبدل التاريخ بصمت.

## معايير قبول الإصدار الأول
1. العميل لا يستطيع قراءة أو استنتاج بيانات عميل آخر حتى بتغيير المعرفات.
2. تظهر جميع حيوانات العميل النشطة فقط، مع دعم إظهار الأرشيف بطلب واضح.
3. تظهر التطعيمات والزيارات والنتائج المعتمدة والفواتير بأرقام مطابقة للنظام الداخلي.
4. الحجز يمنع المواعيد غير المتاحة ويعطي تأكيدًا واضحًا.
5. جميع الشاشات تعمل على 390px وtablet وdesktop مع دعم keyboard وscreen reader.
6. كل تنزيل ملف يستخدم رابطًا مؤقتًا، وكل إجراء حساس مسجل في Audit Log.
