# الخطة الرئيسية لإعادة تطوير نظام أليف بالكامل

## 1. رؤية المنتج
أليف منصة تشغيل بيطرية عربية متكاملة للعيادات والمستشفيات البيطرية، تجمع الاستقبال والسجل الطبي والجراحة والتنويم والمعمل والأشعة والمخزون والفوترة والتواصل مع العميل في نظام سريع وآمن. الهدف هو الاقتراب من مستوى ezyVet وDigitail وShepherd وCovetrus Pulse مع تجربة عربية أبسط وأنسب للعيادات المحلية.

## 2. المستخدمون
- مالك المنشأة والمدير العام.
- مدير الفرع.
- الطبيب البيطري.
- مساعد الطبيب والتمريض.
- الاستقبال وخدمة العملاء.
- المحاسب والخزنة.
- المخزن والمشتريات.
- المعمل والأشعة.
- العميل مالك الحيوان.

## 3. مبادئ التصميم
- RTL عربي أصلي، وليس ترجمة لواجهة أجنبية.
- المسارات اليومية الشائعة لا تزيد عن ثلاث نقرات.
- لوحة مختلفة لكل دور تعرض المطلوب الآن فقط.
- بحث موحد وCommand Palette واختصارات لوحة مفاتيح.
- حالات تحميل وفراغ وخطأ ونجاح واضحة في كل شاشة.
- دعم الكمبيوتر والتابلت والموبايل، وWCAG AA.
- عدم الاعتماد على اللون وحده، وأهداف لمس لا تقل عن 44px.

## 4. الهيكل الوظيفي الكامل

### 4.1 الاستقبال والـFlowboard
- تقويم يومي/أسبوعي مع السحب والإفلات.
- حجز وتأكيد وإلغاء وNo-show وقائمة انتظار.
- Check-in وتحديد أولوية الحالات الطارئة.
- Flowboard لحظي: منتظر، داخل الكشف، معمل، أشعة، صيدلية، دفع، خروج.
- كشف التعارض بين الطبيب والغرفة والمعدات.
- مواعيد متكررة وحجز متعدد الحيوانات لنفس المالك.

### 4.2 العملاء والحيوانات
- ملف عميل 360°: التواصل، الحيوانات، الرصيد، الفواتير، الموافقات، الرسائل.
- ملف حيوان: صورة، النوع والسلالة، العمر، microchip، الوزن، الحساسية، الأمراض المزمنة.
- Timeline طبي ومالي موحد.
- دمج السجلات المكررة مع سجل تدقيق.
- نقل الملكية، حالة متوفى، وحظر التنبيهات غير المناسبة.

### 4.3 السجل الطبي
- SOAP قابل للتخصيص وقوالب حسب نوع الزيارة.
- العلامات الحيوية ومنحنى الوزن وBody Condition Score.
- Problem List وتشخيصات نشطة وسابقة.
- وصفات وأوامر معمل وأشعة وإجراءات وخطة متابعة.
- تنبيه حساسية وتعارض دوائي وجرعة محسوبة بالوزن.
- مرفقات وصور ومستندات وموافقات رقمية.
- قفل السجل بعد الاعتماد مع Amendments بدل التعديل الصامت.

### 4.4 التطعيمات والوقاية
- بروتوكولات حسب القطط/الكلاب والعمر والحالة الصحية.
- جرعة وLot وBatch وصلاحية وشهادة قابلة للطباعة.
- احتساب الاستحقاق القادم وتذكيرات متعددة القنوات.
- منع استخدام مخزون منتهي أو غير كافٍ.

### 4.5 الجراحة والتخدير
- Pre-op checklist وموافقة العميل وتقييم المخاطر.
- خطة التخدير والأدوية والمراقبة الدورية للعلامات الحيوية.
- تسجيل الفريق والأدوات والمستهلكات.
- تقرير العملية وتعليمات الخروج والمتابعة.

### 4.6 التنويم والتمريض
- Whiteboard للأسرة والأقفاص والحالة والأولوية.
- Treatment sheet بجدول الجرعات والمهام والقياسات.
- تسليم ورديات وملاحظات تمريضية وإنذارات الجرعات المتأخرة.
- تحويل كل مستهلك وخدمة تلقائيًا إلى الفاتورة.

### 4.7 المعمل والأشعة
- كتالوج فحوصات وحزم وأسعار ومدة إنجاز.
- طلب، جمع عينة، استلام، تشغيل، مراجعة واعتماد.
- Reference ranges حسب النوع والعمر عند الحاجة.
- نتائج منظمة وملفات PDF وصور وربطها بالزيارة.
- تنبيه القيم الحرجة وسجل من شاهد واعتمد النتيجة.

### 4.8 الصيدلية والمخزون والمشتريات
- مخازن متعددة، باركود، وحدات تحويل، Lot وExpiry.
- موردون، طلب شراء، استلام جزئي، فاتورة مورد، مرتجعات.
- FIFO/FEFO، جرد وتسويات ونقل بين المخازن.
- حدود طلب واقتراح شراء وتقرير راكد وقريب الانتهاء.
- منع الرصيد السالب ومعاملات ذرية مع الفواتير.

### 4.9 الفواتير والخزنة والمحاسبة
- عروض أسعار، فواتير، دفعات جزئية، مرتجعات وCredit Notes.
- خصومات وصلاحيات اعتماد وضرائب وقوائم أسعار.
- ورديات خزنة وفتح/إغلاق وفروق تحصيل.
- أرصدة العملاء والموردين وتقارير الربحية والتدفق النقدي.
- idempotency لمنع تكرار الدفع أو خصم المخزون.

### 4.10 التقارير والإدارة
- لوحة تشغيل لحظية ومؤشرات حسب الدور والفرع.
- الإيراد والربح ومتوسط الفاتورة والتحصيل والديون.
- No-show ومدة الانتظار ووقت الزيارة واستخدام الأطباء.
- دوران المخزون والهالك وقرب الانتهاء.
- Drill-down وتصدير Excel/PDF مع صلاحيات.

### 4.11 التواصل والأتمتة
- WhatsApp/SMS/Email بقوالب وموافقة العميل.
- تأكيد موعد وتذكير وتطعيم ونتيجة معمل وفاتورة ومتابعة.
- Inbox موحد وسجل تسليم وفشل وإعادة محاولة.
- Automations قابلة للتعطيل مع Audit Log.

### 4.12 تعدد الفروع
- Branch وRoom وWarehouse وCashbox ككيانات أساسية.
- المستخدم يرى الفروع المصرح بها فقط.
- أرقام مستندات وقوائم أسعار ومخزون وتقارير حسب الفرع.

## 5. بوابة العميل
بوابة منفصلة مبسطة وآمنة تعرض للعميل بياناته وحيواناته فقط:
- الصفحة الرئيسية: الموعد القادم، التطعيمات المستحقة، الرصيد، التنبيهات.
- كل الحيوانات مع صورة وحالة صحية مختصرة.
- ملف الحيوان: البيانات، الوزن، الحساسية، الأمراض المزمنة، الزيارات، الوصفات، التطعيمات، نتائج المعمل والأشعة، العمليات والمرفقات المسموح بها.
- المواعيد: طلب موعد، إعادة جدولة أو إلغاء ضمن سياسة العيادة.
- الفواتير والمدفوعات والإيصالات والتنزيل.
- تعليمات الخروج وخطة المتابعة وطلب إعادة صرف وصفة وفق سياسة العيادة.
- الرسائل والموافقات وتفضيلات التواصل والخصوصية.

### ضوابط بوابة العميل
- حساب العميل مرتبط بسجل Owner واحد ولا يقبل ownerId من المتصفح.
- كل استعلام يعتمد هوية الجلسة ويطبق object-level authorization.
- الزيارات الداخلية والملاحظات غير المعتمدة لا تظهر للعميل.
- روابط الملفات مؤقتة وموقعة، ولا توجد روابط عامة دائمة.
- MFA اختياري، rate limiting، سجل جلسات، تسجيل خروج من كل الأجهزة.

## 6. معمارية النظام المستهدفة
- Frontend: React + TypeScript + React Query + Router + Design System.
- Backend: NestJS modular monolith في المرحلة الأولى.
- Database: PostgreSQL للإنتاج؛ SQLite فقط للنسخة المحلية الصغيرة والتطوير.
- Storage: S3-compatible للملفات مع signed URLs.
- Queue: Redis/BullMQ للرسائل والتقارير والمهام الطويلة.
- Observability: structured logs، request IDs، metrics، error tracking.
- API: DTO validation، OpenAPI، pagination، filtering، idempotency keys.
- Deployment: Docker، migrations تلقائية محكومة، health/readiness checks.

## 7. نموذج البيانات المطلوب إضافته
- Organization, Branch, Room, Warehouse, Cashbox, Shift.
- ClientAccount وربطه بـOwner دون خلط موظفي العيادة بالعملاء.
- Session/Device وPasswordReset وVerificationCode.
- MedicalProblem, Vital, ClinicalTemplate, Attachment, Consent.
- Drug, DrugInteraction, PrescriptionItem, Dispense.
- LabOrder/LabResult وImagingOrder/ImagingResult.
- Hospitalization, Bed, TreatmentOrder, NursingTask, Observation.
- PurchaseOrder, GoodsReceipt, InventoryLot, Transfer, StockCount.
- Quote, Refund, CreditNote, CashMovement.
- Message, MessageTemplate, DeliveryAttempt, CommunicationConsent.
- AuditEvent append-only مع before/after وrequestId.

## 8. الأمن والاعتمادية
- عدم وجود JWT secret افتراضي في الإنتاج.
- Refresh token rotation وتخزين hash ورصد reuse.
- RBAC + branch scope + ownership scope.
- تشفير النسخ الاحتياطية والحقول الحساسة عند الحاجة.
- CSP/CORS/Helmet، rate limits، lockout تدريجي، وسياسة كلمات مرور.
- Audit غير قابل للتعديل لكل حدث طبي أو مالي حساس.
- نسخ احتياطي يومي واختبار استعادة شهري.
- RPO أقل من 24 ساعة محليًا وأقل من 15 دقيقة سحابيًا؛ RTO موثق.

## 9. استراتيجية الاختبارات
- Unit للخدمات والحسابات والصلاحيات.
- Integration مع قاعدة بيانات اختبار حقيقية.
- API contract واختبارات authorization لكل دور وownership.
- E2E: تسجيل الدخول، الحجز، الزيارة، الوصفة، الفاتورة، الدفع، المخزون، بوابة العميل.
- Accessibility وresponsive وvisual regression.
- Load tests للبحث والـFlowboard والتقارير.
- اختبارات backup/restore وmigration rollback.

## 10. مراحل التنفيذ

### المرحلة 0 — تثبيت الأساس (أسبوعان)
- توحيد الخادم وإزالة الكود القديم المتكرر.
- إصلاح CI والأسرار والإعدادات والمigrations.
- Design tokens ومكونات UI الأساسية ومعالجة الأخطاء.
- اختبار أهم مسارات النظام الحالية.

### المرحلة 1 — الهوية والصلاحيات والفروع (أسبوعان)
- Organization/Branch، RBAC دقيق، جلسات وأجهزة.
- ClientAccount منفصل وربط آمن بالمالك.
- تدقيق وصلاحيات object-level.

### المرحلة 2 — الاستقبال والملف الطبي (3 أسابيع)
- Flowboard وتقويم وملف 360° وSOAP وقوالب ووصفات.
- تحسين البحث والاختصارات وتجربة التابلت.

### المرحلة 3 — بوابة العميل (3 أسابيع)
- Dashboard والحيوانات والسجل المنشور والتطعيمات والمواعيد والفواتير.
- رسائل وموافقات وتفضيلات خصوصية.

### المرحلة 4 — المخزون والمشتريات والمالية (3 أسابيع)
- Lots/expiry، مشتريات، جرد، خزنة، refunds وcredit notes.

### المرحلة 5 — الجراحة والتنويم والمعمل والأشعة (4 أسابيع)
- الوحدات السريرية المتقدمة والـwhiteboards والنتائج والمرفقات.

### المرحلة 6 — التقارير والتواصل والذكاء (3 أسابيع)
- KPIs وdrill-down ورسائل وأتمتة ومساعد كتابة سريري بمراجعة الطبيب.

### المرحلة 7 — الاستعداد للإنتاج (أسبوعان)
- Security review، performance، backup restore، تدريب، pilot، خطة rollback.

## 11. بوابات الجودة لكل مرحلة
- متطلبات وقبول مكتوبة لكل Story.
- نجاح typecheck/build/tests وCode Review.
- لا توجد ثغرات High/Critical أو أسرار.
- فحص صلاحيات سلبي: المستخدم لا يرى بيانات غير مصرح بها.
- فحص responsive على 390px وtablet وdesktop.
- توثيق migration وrollback والمراقبة.

## 12. مؤشرات النجاح
- متوسط check-in أقل من دقيقة.
- إنشاء زيارة أساسية أقل من دقيقتين دون الكتابة السريرية.
- p95 للعمليات اليومية أقل من 500ms داخل الشبكة.
- خفض أخطاء المخزون والفواتير المكررة إلى صفر عبر القيود والمعاملات.
- أكثر من 80% من العملاء يستطيعون الوصول للتطعيمات والفواتير دون اتصال بالعيادة.
- تتبع 100% من التعديلات الطبية والمالية الحساسة.

## 13. تعريف اكتمال المنتج
لا يعد النظام مكتملًا لمجرد ظهور الشاشات. الاكتمال يعني: صلاحيات صحيحة، بيانات حقيقية، اختبارات، حالات خطأ وفراغ، طباعة وتصدير، مراقبة، نسخ احتياطي واستعادة، توثيق، وتدريب مستخدمين ناجح في Pilot فعلي.
